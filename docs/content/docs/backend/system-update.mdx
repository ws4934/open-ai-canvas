# 网页更新与程序回退

管理员打开“系统设置 → 系统更新”，点击“立即更新”。程序从 `ws4934/open-ai-canvas` 的 GitHub Release 下载新版，校验后等待正在执行的任务完成，保留上一版程序并替换文件；Docker 自动重启，页面自动重连。

前端、Agent 代码与锁定依赖、完整官方插件都在同一个 Go 程序中。外部 Nginx/Caddy 只反代应用端口，不参与更新。

## 发布新版本

先提交对应的 `VERSION` 与 `CHANGELOG.md`，然后任选一个入口：

- 推送 `v*` tag。
- 在 GitHub Actions 手动运行发布任务，填写与提交一致的版本号。

发布任务固定提交，执行质量检查、前端构建、AMD64/ARM64 程序构建和镜像验收。两种架构复用前端产物；镜像使用同一批 Go 文件。资产上传到草稿 Release，全部成功后才公开。已正式发布的同名版本不覆盖，修正需使用新版本号。

后端测试分为 `app-1`…`app-4` 和 `rest` 五个并行分片。`Backend checks` 汇总全部分片，并核对依赖 PostgreSQL / Redis 的用例确实执行；任一分片失败都会阻断发布。

正式资产为：

```text
open-ai-canvas_<带v版本>_linux_amd64.tar.gz
open-ai-canvas_<带v版本>_linux_arm64.tar.gz
SHA256SUMS
docker-compose.deploy.yml
```

普通 main 提交不会成为网页推荐的新版本。稳定版支持三段和四段数字，草稿和预发布版不参与推荐。只有同时提供当前架构程序包和 `SHA256SUMS` 的版本可安装。

## 更新时发生什么

1. 后端读取 Release，检查结果缓存 20 分钟；手动“检查更新”会强制刷新。GitHub 失败会明确报错。
2. 后台下载匹配架构的程序并验证 SHA-256，安全解包后运行新版的只读 `--check`。
3. 暂停接收新任务，但现有 Agent 的媒体审批预检、规格调整及派生模型/媒体任务仍可继续执行。内部续执行须匹配已登记的活动 Agent、账号与画布，仍执行模型、资源、预算和审批校验；不存在或已结束的运行不能借用该通路。
4. 最多等待 10 分钟；审批、用户输入或未结束任务阻塞时，不强行终止业务。
5. 旧程序保留为 `.backup`，使用同一文件系统中的 rename 替换；替换失败恢复旧文件。
6. 当前程序优雅退出，Docker 通过 `restart: unless-stopped` 启动新程序。
7. 新程序释放自身 Agent/插件资源，完成数据库启动迁移和运行检查后记录成功。

关闭浏览器不会取消后台更新。页面短暂断线只表示正在重连，最终结果以持久化状态为准。

## 程序不会随容器重建丢失

官方镜像从以下持久化位置运行：

```text
/data/system/bin/yingce-backend
/data/system/bin/yingce-backend.backup
/data/system/update.json
```

首次空目录才复制镜像中的初始程序。重启或重建容器继续使用持久化程序，不会悄悄恢复到镜像初始版本。只换 Docker 镜像不会覆盖这个程序；基础环境升级后，再从网页安装所需业务版本。

Node 与系统运行环境由镜像提供，Agent JS/依赖和官方插件随程序提供。新版要求更高基础环境时，在替换之前提示更新镜像，服务器不现场安装 npm 依赖。

## 回退上一版程序

网页回退先执行旧程序的 `--check-schema`，确认其可读取当前数据库，再替换程序并重启。回退不清空数据库、不恢复整库、不删除创作文件。数据库结构不兼容时拒绝强行回退。

如果网页无法访问，先查看应用日志；需要恢复上一版程序时，在部署目录执行：

```bash
docker compose -f docker-compose.deploy.yml stop backend
docker compose -f docker-compose.deploy.yml run --rm --no-deps --user app \
  --entrypoint /data/system/bin/yingce-backend.backup \
  backend --restore-program
docker compose -f docker-compose.deploy.yml up -d backend
```

恢复命令失败时不要继续强制替换或删除数据，按输出检查数据库版本和备份程序。业务数据库、资源与配置仍需部署者另行备份；程序备份不代替数据备份。

## 管理 API

沿用管理员鉴权及业务信封：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/admin/system-update` | 当前程序、最近检查结果、操作状态、上一版程序 |
| `POST /api/admin/system-update/check` | `{force:false}` 使用缓存，默认或 `{force:true}` 强制检查 |
| `POST /api/admin/system-update/start` | `{targetVersion}` 发起异步更新，立即返回操作 ID |
| `POST /api/admin/system-update/rollback` | `{reason}` 检查旧程序后异步回退 |

同一更新重复提交不会重复替换程序。操作日志存入数据卷，重启后仍可读取。源码开发可以检查版本，但不具备受管运行路径时禁止替换程序。

## 安装

使用统一应用镜像，只运行 backend、PostgreSQL 和 Redis。安装命令与端口配置见[Docker 部署](/docs/overview/docker)。
